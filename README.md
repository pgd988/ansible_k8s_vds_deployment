# Bare-Metal Kubernetes Cluster with Ansible

These Ansible playbooks automate the deployment of a bare-metal Kubernetes cluster on Ubuntu VDS/VMs, installing `containerd`, `kubeadm`, `kubelet`, `kubectl`, and the `Calico` network plugin.

## Prerequisites
- Ansible installed on your control machine.
- SSH access to the target Ubuntu VMs/VDS with sudo privileges.
- Update `inventory.ini` with the IPs and usernames for your target servers.
- Update `vars.yml` with the desired versions and your target control plane API server advertise address.

## Usage

### 1. Configure the Control Plane

Run the control plane playbook:

```bash
ansible-playbook -i inventory.ini control-plane-node.yml
```

This will output `join_command.sh` and `ca_cert_hash.txt` in your local directory for future use by the worker nodes.

#### Next Steps after Control Plane Init:

As instructed by the `kubeadm init` process, to start using your cluster, you need to run the following as a regular user on your control plane node:

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

Alternatively, if you are the root user, you can run:

```bash
export KUBECONFIG=/etc/kubernetes/admin.conf
```

### 2. Configure the Worker Nodes

Run the worker node playbook to join the workers to the cluster:

```bash
ansible-playbook -i inventory.ini worker-node.yml
```

> **Note**: This playbook uses the `join_command.sh` generated by the control plane playbook. If you need to add nodes manually later, you can use the `<control-plane-host>:<control-plane-port> --token <token> --discovery-token-ca-cert-hash sha256:<hash>` command directly on the worker node.
